# ADR 0003: API 계약: 스펙 우선 (OpenAPI + AsyncAPI)

- 상태: 채택
- 날짜: 2026-10-28

## 맥락

레포가 나뉘어 있어 계약이 레포 간 유일한 연결점이다. 코드 우선(데코레이터로 스펙 생성)과 스펙 우선(YAML 먼저)을 비교했다.

## 결정

HTTP는 OpenAPI, Kafka 이벤트는 AsyncAPI로 **YAML을 먼저 작성·리뷰**한다. NestJS에서는 Hey API `nestjs` 플러그인으로 컨트롤러 타입을 생성하고, 스펙 기반 런타임 검증 미들웨어(`express-openapi-validator` 1순위)로 요청·응답을 검증한다. DTO 클래스나 `@nestjs/swagger`로 스키마를 이중 정의하지 않는다. 스펙은 semver 패키지로 배포한다.

## 결과

- 소비자가 백엔드 구현 전에 목 서버로 개발할 수 있다
- API 설계를 구현과 분리해 리뷰할 수 있다
- 대가: Nest의 기본(코드 우선)과 다른 길이라 툴체인을 직접 조합해야 한다. Hey API 플러그인은 베타다 → 0단계 POC로 검증

## 검토한 대안

- 코드 우선(@nestjs/swagger): Nest 생태계 기본값이지만 스펙이 구현에 끌려간다
- 스펙에서 추상 컨트롤러 + class-validator DTO를 생성하는 도구들: 생태계가 작고 미성숙

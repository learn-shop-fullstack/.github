# ADR 0004: 이벤트 브로커: Kafka + 트랜잭셔널 아웃박스, 지연 처리는 DB 스윕

- 상태: 채택
- 날짜: 2026-10-28

## 맥락

주문·결제·배송 이벤트를 재고, 알림, 검색 색인, 분석이 각자 소비한다. 참고 프로젝트는 RabbitMQ를 썼고, BullMQ(Redis)도 검토했다.

## 결정

Kafka를 쓴다. 상태 변경과 같은 트랜잭션에서 아웃박스에 기록하고 릴레이가 Kafka로 발행한다. 메시지 키로 주문별 순서를 보장하고, 팬아웃은 컨슈머 그룹으로 한다. 재시도·DLQ는 재시도 토픽 + DLT로 직접 구현한다. 결제 타임아웃 같은 지연 처리는 Kafka로 하지 않고 DB 기한 컬럼 + `FOR UPDATE SKIP LOCKED` 스윕으로 한다. 클라이언트는 `@confluentinc/kafka-javascript`를 Nest 모듈로 직접 감싼다(KafkaJS는 유지보수 중단, Nest Kafka 트랜스포트는 KafkaJS 기반).

## 결과

- 국내 이커머스 채용 시장에서 많이 쓰는 기술을 경험한다
- 재처리(오프셋 리셋), 컨슈머 랙 같은 운영 지표를 다룬다
- 대가: 재시도·지연 처리를 직접 만들어야 한다. JVM 서비스라 메모리를 많이 쓴다(ADR 0010)

## 검토한 대안

- RabbitMQ: 라우팅·DLX가 기본 제공되지만 지연 처리는 우회가 필요하고, 재처리가 안 된다
- BullMQ: Node 친화적이고 지연 작업이 기본이지만 팬아웃이 약하다

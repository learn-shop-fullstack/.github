# ADR 0006: 검색: OpenSearch + Nori를 처음부터 도입

- 상태: 채택
- 날짜: 2026-10-28

## 맥락

상품 검색은 마켓플레이스의 핵심 기능이고, 한국어 형태소 분석이 필요하다. Postgres `pg_trgm`으로 시작하는 안과 비교했다.

## 결정

처음부터 OpenSearch + Nori 분석기를 쓴다. 원본은 Postgres이고, OpenSearch는 `product.events`를 소비하는 색인 컨슈머가 갱신하는 읽기 전용 사본이다. 별칭 + 버전 인덱스로 무중단 재색인한다. Nori는 동의어를 처리하지 않으므로 동의어·사용자 사전을 따로 관리한다.

## 결과

- Apache 2.0 라이선스로 Elasticsearch 계열 매핑·쿼리를 배운다
- Kafka 이벤트 기반 동기화를 처음부터 경험한다 → 아웃박스·Kafka 기반을 3단계로 앞당겼다
- 대가: 메모리 부담(ADR 0010), DB와 인덱스 정합성 관리 필요

## 검토한 대안

- `pg_trgm`으로 시작 후 전환: 단순하지만 한국어 검색 품질이 낮고 나중에 구조를 다시 짜야 한다

# ADR 0013: 스펙 공통 규약: camelCase + RFC 9457 Problem Details + AIP-158 페이지네이션, Redocly 린트로 강제

- 상태: 채택
- 날짜: 2026-10-28

## 맥락

ADR 0012로 툴체인을 확정했지만 스펙의 모양(이름 표기, 에러 형식, 목록 응답)은 정하지 않았다. 이 셋은 web·loadtest 클라이언트가 모두 따르므로 첫 엔드포인트 이후에 바꾸면 BREAKING이 된다. 또 0012의 보완책 두 가지(`additionalProperties: false` 강제, `required`/`properties` 불일치 검출)를 리뷰가 아닌 도구로 막아야 한다. 기준은 자체 규칙보다 널리 쓰이는 표준을 따르는 것이다.

## 결정

세부 규칙의 원본은 `shop-sim-api/openapi/CONVENTIONS.md`다. 여기에는 되돌리기 어려운 선택만 적는다.

- **표기**: 경로는 kebab-case 복수 명사, 파라미터·JSON 필드·`operationId`는 camelCase, 스키마 이름은 PascalCase, enum 값은 UPPER_SNAKE_CASE.
- **엄격성**: 모든 object 스키마에 `additionalProperties: false`. 요청의 모르는 필드는 400, 응답의 초과 필드는 런타임 응답 검증이 500으로 막는다.
- **에러**: 모든 4xx·5xx는 RFC 9457 `application/problem+json`. 클라이언트는 `type`으로만 분기하고, 구분이 필요한 오류는 `/problems/<kebab-case>` type을 계약으로 등록한다. 검증 오류는 `errors[{ pointer, detail }]`. 상태 충돌은 409, 422는 쓰지 않는다.
- **페이지네이션**: Google AIP-158 커서 방식(`pageSize`, `pageToken` → `{ items, nextPageToken }`)이 기본. 행 번호 이동과 전체 개수가 필요한 그리드 목록(AG Grid)만 `skip`(상한 10000) → `totalSize`를 더한다. 토큰은 불투명하고 발급 조건(필터·정렬)을 담는다.
- **강제**: Redocly CLI `lint`(recommended + 내장 규칙 + configurable rule)를 레포 루트 `redocly.yaml`로 설정한다. `security-defined`는 인증이 정해지는 4단계까지 끈다.

## 결과

- 생성 타입·컨트롤러·클라이언트 코드에 변환 계층 없이 스펙 이름이 그대로 쓰인다(TypeScript 관례와 같은 camelCase)
- 클라이언트의 오류 처리가 문구가 아닌 `type` 계약에 묶인다. `/problems/*`의 이름 변경·삭제는 BREAKING이다
- 대가와 보완책
  - `additionalProperties: false`는 하위 호환에 불리하다: 서버보다 먼저 새 필드를 보내는 클라이언트는 거부된다 → "스펙 → 서버 → 클라이언트" 순서로 배포한다
  - `allOf`로 합친 스키마는 `additionalProperties: false`와 충돌한다 → `unevaluatedProperties: false`를 쓰고, 처음 쓸 때 Hey API·검증기·린트를 다시 확인한다
  - `type`을 생략한 object 스키마는 `additionalProperties` 린트를 빠져나간다 → 규약상 `type` 필수, 리뷰로 확인
  - 오프셋은 `skip`이 클수록 느리고 1만 건 너머로 이동할 수 없다 → 그 규모의 그리드는 기간 필터 등으로 범위를 좁힌다(7단계 이후 재검토)
  - 린트를 CI 필수 검사로 거는 일은 1단계

## 검토한 대안

- **snake_case 필드**: 처음에 골랐다가 되돌렸다. TypeScript 코드에 snake_case가 섞이거나 변환 계층이 필요하고, Google API JSON 등 참고한 표준이 camelCase다
- **에러 형식 자체 정의 / `code` 문자열 필드**: RFC 9457이 `type` URI로 같은 역할을 하고 express-openapi-validator 오류와 필터(0012)가 이미 이 형식이다
- **오프셋만(`page`·`size`) 또는 커서만**: 오프셋만 쓰면 무한 스크롤·대량 목록에서 느리고 중복·누락이 생긴다. 커서만 쓰면 AG Grid의 행 번호 이동·전체 개수 표시를 할 수 없다
- **Spectral**: 같은 일을 하지만 Redocly configurable rule만으로 [린트] 규칙을 모두 구현할 수 있었다(규칙마다 위반 예시로 확인)

# ADR 0017: API 클라이언트 생성 도구: Hey API, 서버 호출과 오류 정규화는 공용 코드로

- 상태: 채택
- 날짜: 2026-10-29

## 맥락

ADR 0003은 web·loadtest가 스펙 패키지에서 클라이언트를 생성한다고 정했지만 도구는 정하지 않았다. 스토어는 Next.js 서버 컴포넌트에서 세션 쿠키를 넘겨 미리 가져오고(prefetch) 브라우저에서 TanStack Query로 이어받는다. 셀러센터·어드민은 SPA, loadtest는 Node다. POC(shop-sim-web#1)로 Hey API, openapi-typescript + openapi-fetch, Orval을 같은 스펙 패키지·시나리오로 비교하고, SSR 하이드레이션은 실제 브라우저와 요청 헤더를 기록하는 서버로 측정했다.

## 결정

- **도구**: `@hey-api/openapi-ts`(백엔드 ADR 0012와 같은 도구, 정확한 버전 고정, POC는 0.99.0). 플러그인은 `@hey-api/typescript`, `@hey-api/sdk`, `@hey-api/client-next`, `@tanstack/react-query`. 입력은 버전 고정된 스펙 패키지의 YAML이고 생성물은 커밋하지 않는다.
- **위치**: 각 레포의 `packages/api-client`가 생성물과 아래 공용 코드를 가진다. 앱은 생성 함수를 직접 쓰지 않고 이 패키지를 통해 쓴다.
- **서버 호출**: 서버 컴포넌트는 쿠키를 담은 클라이언트를 요청마다 만드는 공용 함수로만 호출한다. 쿠키를 요청 옵션 `headers`로 넘기지 않는다.
- **오류 정규화**: 생성 클라이언트의 오류 인터셉터에서 네트워크 오류, JSON이 아닌 본문, 스펙에 없는 상태 코드를 `Problem`과 구분되는 오류 타입으로 바꾼다. 화면 코드는 정규화된 타입으로만 분기한다.
- **목**: 화면 개발은 같은 스펙 패키지를 서빙하는 Prism 목 서버를 쓴다.

## 결과

- 생성기 하나로 백엔드 타입·web·loadtest 클라이언트를 만들어, 0.x 업그레이드 확인을 한 도구에서만 한다
- API 주소는 실행 시점 설정(`runtimeConfigPath`)으로 정해지고, 함수 이름이 `operationId`라 사용처를 검색할 수 있다
- 대가와 보완책
  - queryKey에 요청 `headers`가 들어가 서버에서 쿠키 헤더로 prefetch하면 브라우저가 다시 요청한다(측정) → 위 "서버 호출" 규칙. 서버와 브라우저는 같은 `baseUrl`을 써야 키가 같다
  - 네트워크 오류일 때 `response` 없이 `error`가 오는데 타입은 `Problem`이다 → 위 "오류 정규화" 규칙. 인터셉터 구현은 1단계 `api-client` 첫 단계에서 확인한다(POC에서는 코드만 확인)
  - MSW 목을 생성하지 않는다 → 테스트에서 필요해지면 재검토
  - 쓰지 않는 SSE 클라이언트 코드도 생성된다. 화면 고유 JS는 Orval보다 컸다(엔드포인트 1개, 압축 7.3KB 대 4.1KB) → 엔드포인트가 늘 때 7단계 전후로 다시 잰다
  - `runtimeConfigPath`에 `.ts` 확장자를 붙이면 생성물 import가 TS5097로 깨진다 → 확장자 없이 쓴다
- 다른 출처 API로의 브라우저 요청에 쿠키가 실리지 않는 문제(fetch 기본 `credentials: 'same-origin'`)는 도구와 무관하다 → 1단계 하위 도메인·CORS 결정에서 다룬다

## 검토한 대안

- **Orval 8.45.0**: queryKey가 URL뿐이라 SSR이 그대로 되고 MSW 핸들러를 생성한다. 그러나 기본값은 4xx를 반환해 TanStack Query가 성공으로 처리하고(실행 확인, `forceSuccessResponse`로 바뀜), API 주소가 생성 시점에 코드에 고정되어 실행 시점 설정에는 mutator를 직접 작성해야 하며, 백엔드와 도구가 둘이 된다
- **openapi-typescript 7.13.0 + openapi-fetch 0.17.0**: 타입 파일 하나만 생성해 가장 가볍고 네트워크 오류를 throw해 정직하다. 그러나 peer가 TypeScript `^5.x`라 6이 지원 범위 밖이고, 마지막 릴리스가 2026-02이며, `openapi-react-query` 0.5.4에 `mutationOptions`가 없고, queryKey에 요청 옵션 전체가 들어가는 문제는 Hey API와 같다

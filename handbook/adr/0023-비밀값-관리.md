# ADR 0023: 비밀값 관리: PC의 권한 제한된 파일이 원본, 비밀번호 관리자에 백업

- 상태: 채택
- 날짜: 2026-10-31

## 맥락

레포에는 `.env.example`만 두고 실제 값은 레포 밖에 두기로 했다(working-agreement, infra 레포 규칙). 운영 compose(shop-sim-infra#8)와 터널(shop-sim-infra#10)로 실제 비밀값이 생겼고, 앞으로 R2 키, 인증 비밀값, OAuth 클라이언트 비밀값, 결제 테스트 키가 더해진다.

- 운영(staging·production)은 로컬 PC 한 대에서 compose로 돌고, 배포는 pull 방식이다. CI는 이미지를 GHCR에 올리기까지만 한다(ADR 0014). CI가 운영 비밀값을 쓸 일이 없다.
- PC를 잃어도 하루 안에 복구하는 것이 목표다(architecture.md).
- 모든 org 레포가 public이다. 지금은 GitHub secret scanning과 push protection이 꺼져 있다.

## 결정

- **운영 원본**: PC의 `~/.config/shop-sim/<환경>/`. 디렉터리는 700, 파일은 600. 환경마다 compose env 파일 하나와 터널 자격 증명 JSON을 둔다. 배포 에이전트와 compose가 이 경로를 읽는다.
- **생성**: 비밀번호처럼 우리가 정하는 값은 사람이 고르지 않고 무작위로 만든다(infra 스크립트). 이미 있는 파일은 덮어쓰지 않는다.
- **백업**: 비밀번호 관리자에 환경별 env 파일과 터널 자격 증명을 보관한다. 값을 바꾸면 관리자에도 반영한다.
- **GitHub Secrets**: CI가 실제로 쓰는 비밀값만 둔다. 지금은 없다(GHCR 푸시는 워크플로 토큰). 빌드에 들어가는 공개 값(웹 앱의 API 주소, ADR 0020)은 Secrets가 아니라 Variables에 둔다.
- **유출 방지**: 모든 org 레포에서 secret scanning과 push protection을 켠다.
- **계정 인증서**(`cert.pem` 같은, 자원을 만들 때만 쓰는 사람의 자격 증명): 운영 원본에 두지 않고 백업하지 않는다. 잃으면 다시 로그인해 받는다.

## 결과

- 운영 비밀값이 한 곳에 있고, 컨테이너는 그 경로만 읽는다
- PC를 잃으면 비밀번호 관리자에서 파일을 되살려 같은 경로에 두면 된다
- public 레포에 알려진 형식의 비밀값(토큰, 클라우드 키)을 푸시하면 GitHub가 막는다
- 대가와 보완책
  - 관리자와 PC 파일이 어긋날 수 있다(동기화는 사람이 한다) → 값을 바꾸는 절차에 "관리자 갱신"을 넣고, 백업 복구 리허설 때 함께 확인한다
  - 변경 이력이 남지 않는다(레포 밖 파일) → 어떤 변수가 있는지는 `.env.example`이 원본이고, 값의 변경은 이슈에 "바꿨다"만 남긴다
  - push protection은 알려진 형식만 잡는다. DB 비밀번호 같은 임의 문자열은 잡지 못한다 → 리뷰와 `.gitignore`, 레포 밖 경로 규칙에 기댄다
  - 파일 권한(600)은 같은 PC의 다른 사용자만 막는다. 이 사용자로 도는 프로세스는 읽을 수 있다 → 운영 PC에서 신뢰하지 않는 코드를 돌리지 않는다(self-hosted runner를 두지 않는 이유와 같다, ADR 0014)

## 검토한 대안

- **SOPS + age로 암호화해 레포에 커밋**: 변경 이력이 남고 배포 에이전트가 복호화해 쓸 수 있다. 그러나 age 개인키는 여전히 레포 밖 백업이 필요하고, public 레포에 암호문이 영구히 남는다. 비밀값 수가 적은 지금은 도구 비용이 크다
- **백업 없이 재발급**: 가장 단순하다. 그러나 외부 서비스 키를 하나씩 다시 받는 수작업이 복구 시간을 늘린다
- **운영 비밀값을 GitHub Secrets에 두고 CI가 배포**: 원본이 한 곳이 된다. 그러나 pull 방식(ADR 0014)에서는 CI가 PC에 접근하지 않아 쓸 데가 없고, public 레포 워크플로에 운영 비밀값을 노출하는 경로가 생긴다
- **macOS 키체인**: OS가 암호화해 보관한다. 그러나 compose가 바로 읽지 못해 꺼내는 래퍼가 필요하다

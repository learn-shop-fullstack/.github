# ADR 0024: 이미지 빌드와 GHCR 게시: arm64 호스팅 러너, 커밋 SHA 태그, 공개 패키지

- 상태: 채택
- 날짜: 2026-10-31

## 맥락

CI는 arm64 이미지를 빌드해 GHCR에 올리기까지만 하고, PC의 배포 에이전트가 받아 교체한다(ADR 0014). 배포 방식은 infra가 소유하고 앱 레포는 재사용 워크플로를 호출만 한다(infra 레포 규칙).

- 이미지를 만들 서비스: api, worker, store, seller, admin, OpenSearch(Nori 플러그인, 지금은 PC에서 빌드)
- 웹 앱은 API 주소를 빌드할 때 넣어 환경마다 이미지를 따로 만든다(ADR 0020). 이 값은 공개 값이고 Variables에 둔다(ADR 0023)
- 모든 org 레포가 public이다. GitHub 호스팅 표준 러너는 public 레포에서 무료이고 arm64 Linux 러너(`ubuntu-24.04-arm`)가 있다
- GHCR 패키지는 public으로 바꾸면 private로 되돌릴 수 없다

## 결정

- **러너**: GitHub 호스팅 arm64 러너(`ubuntu-24.04-arm`)에서 네이티브로 빌드한다. 플랫폼은 `linux/arm64` 하나다.
- **재사용 워크플로**: shop-sim-infra `.github/workflows/`에 둔다. 앱 레포는 `@main`으로 호출한다. 입력은 추가만 하고, 호환이 깨지는 변경은 새 워크플로 파일로 낸다.
- **이미지 이름**: 서비스마다 `ghcr.io/learn-shop-fullstack/shop-sim-<서비스>`(`shop-sim-api`, `shop-sim-store`, `shop-sim-opensearch` 등).
- **태그**: 커밋 SHA로 붙이고 덮어쓰지 않는다. 환경과 무관한 이미지는 `sha-<7자>`, 환경마다 빌드하는 웹 이미지는 `<환경>-sha-<7자>`. `latest` 같은 움직이는 태그는 두지 않는다. 어떤 태그를 어느 환경에 배포할지는 배포 에이전트·환경 분리 항목에서 정한다.
- **빌드 시점**: main에 푸시될 때(머지) 빌드해 올린다. PR에서는 올리지 않는다(빌드 검사는 각 레포 CI).
- **공개 여부**: 패키지를 public으로 둔다. PC는 로그인 없이 받는다.
- **환경별 빌드 값**: 앱 레포의 GitHub Environments(`staging`, `production`) Variables에 둔다. 재사용 워크플로가 환경 입력을 받아 그 환경으로 job을 돌리고 값을 빌드 인자로 넘긴다(호출하는 job은 `environment`를 쓸 수 없다).

## 결과

- QEMU 에뮬레이션 없이 PC와 같은 아키텍처로 빌드하고 비용이 없다
- PC에 GHCR 토큰이 필요 없어 운영 비밀값이 늘지 않는다
- 이미지 태그로 어느 커밋이 배포됐는지 알 수 있고, 이전 태그로 되돌릴 수 있다
- 대가와 보완책
  - public 이미지는 누구나 받는다. 되돌릴 수 없다 → 이미지에는 공개 값만 넣는다. 비밀값은 실행할 때 env 파일로 주입한다(ADR 0023). 빌드 인자에 비밀값을 넘기지 않는다
  - `@main` 호출이라 infra의 실수가 모든 앱 배포를 바로 깬다 → 입력 호환을 지키고, 바꿀 때는 한 앱에서 먼저 돌려 본다
  - 웹 이미지가 환경마다 생겨 staging에서 확인한 이미지와 production 이미지가 바이트 단위로 같지 않다 → 같은 커밋 SHA에서 빌드하고, 다른 것은 빌드 값뿐이게 한다(ADR 0020의 대가)
  - 태그가 쌓인다 → 보존 정책은 저장 용량이 문제 될 때 정한다
  - 움직이는 태그가 없어 에이전트가 "새 이미지"를 알려면 레지스트리를 조회하거나 배포할 태그를 따로 받아야 한다 → 배포 에이전트 항목에서 정한다
  - 재사용 워크플로에서 `vars`가 호출한 레포의 환경 값으로 읽히는지는 문서에 명시가 없다 → 구현에서 확인하고, 안 되면 이 ADR을 다시 본다

## 검토한 대안

- **amd64 러너 + buildx(QEMU)**: 러너 선택지가 넓다. 그러나 에뮬레이션이라 Next.js 빌드가 몇 배 느리고, arm64 러너가 무료라 이유가 없다
- **멀티 아키텍처(amd64 + arm64) 이미지**: 다른 기계로 옮기기 쉽다. 그러나 실행 환경이 arm64뿐이라 빌드 시간만 두 배다. 필요해지면 플랫폼을 더한다
- **private 패키지 + PC에 읽기 토큰**: 이미지가 공개되지 않는다. 그러나 레포가 이미 public이라 숨길 것이 적고, 만료되는 토큰을 PC 비밀값으로 관리해야 한다
- **`latest`·`main` 같은 움직이는 태그**: 에이전트가 같은 태그만 다시 받으면 된다. 그러나 어느 커밋이 돌고 있는지 태그로 알 수 없고 되돌리기가 어렵다
- **재사용 워크플로를 SHA나 릴리스 태그로 고정**: 호출 쪽이 안정적이다(GitHub 권장). 그러나 infra를 바꿀 때마다 모든 앱 레포를 고쳐야 한다. 호출하는 레포가 api·web 둘뿐인 지금은 `@main`과 입력 호환 규칙으로 충분하다
